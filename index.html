Work

Replying to clinic leads before they go elsewhere

2026 · Python · Gmail API · Google Calendar · Railway

Problem
A clinic that answers a web form the next morning has usually lost that patient. I wanted to sell an automatic reply to clinics, but I had never run one.
Decision
I put it on my own site first and refused to offer it until it worked there. That test is how I found my contact page still embedding an old booking calendar that the system couldn't see, so a lead who booked there would have been chased anyway. I moved booking to Google Calendar so the worker can check it.
Result
In the end-to-end test a filled form got a personal reply with a booking link in about 4 minutes. The booking was detected and no follow-up went out. Leads who neither reply nor book get exactly one follow-up after 24 hours.

Sorting a recruiter's inbox into vacancies

2026 · Python · IMAP/Gmail OAuth · Claude · desktop app and web

Problem
A recruiter received applications for several open roles in one inbox, mixed with everything else, and read each CV by hand.
Decision
After the first real run, the open question was whether to make the email filters configurable. I decided not to. The classifier had sorted every email correctly, so the risk was a settings screen nobody would use well. I made the rules file readable and added a button to open it instead. The same run showed that "KAM" and "Key Account Manager" were opening two vacancies for one role, which no test with sample data had caught.
Result
First run on the real inbox: 30 emails, 30 CVs, each in the right vacancy. A later batch of 100 emails found 45 CVs for about $0.25 in model cost.

A job application co-pilot that can't press Submit

2026 · Python · Playwright · Claude · PyInstaller

Problem
Applying for jobs means retyping the same answers into long forms. Tools that rewrite CVs with AI also tend to add achievements that never happened.
Decision
The first version could auto-apply on LinkedIn. I deleted it, about 1,000 lines. It needed the user's password stored in plain text, typing it from a fresh browser is what gets accounts flagged, and LinkedIn's login now uses element ids that change on every render. The co-pilot works in a real browser instead, and the Submit button is blocked in code, not only in the prompt.
Result
26 to 70 seconds and $0.05 to $0.12 per form. Once I fixed the CV parser the match score started to mean something: 32-39 for a role that didn't fit and 80-82 for one that did. Before the fix both scored under 20.

Research tables that are checked by something else

2026 · Python · pandas · SciPy · Word

Problem
A research team built the results tables of a technical report on rural water and sanitation by hand from a large dataset. A single wrong figure spreads into every chapter that cites it.
Decision
It would have been faster to let the model write both the code that builds the tables and the checks. I kept them apart. If the same model misreads the data in both places, the check passes and the error ships. The checks compare against the report that was already delivered and reviewed.
Result
The pipeline passes 63 of 63 checks and reproduces the delivered report with 0 differences, in under 30 seconds. It also found on its own that a coverage column equals three other columns added up and divided by households, true in 4,896 of 4,896 rows. Before, that relation had been worked out by hand.

One manager agent for eight specialists

2026 · Python · Node · Claude tool use · Postgres · Railway · GitHub Actions

Problem
Separate bots for WhatsApp, leads, ads and content meant separate places to operate them and nobody looking at the whole.
Decision
Prices and event details used to live in the bot's code, so every change was a deploy. I moved them into a table in the shared database that the bot rereads every minute. Code changes still go through git, on purpose.
Result
73 actions across 8 agents, live around the clock. A price changed from chat reached the live WhatsApp bot in about 30 seconds with no deploy. For the security tests I broke one defense at a time on purpose; the tests caught 10 of 10.

An outreach campaign in one day

2026 · Python · Apollo API · SMTP/IMAP

Problem
A B2B client in Panama lost a partner institution shortly before a regional tour and needed new ones to contact right away.
Decision
I sent from the client's own established mailboxes instead of setting up a new sending domain that day. A fresh domain needs weeks of warm-up, and the tour didn't have weeks. The contact data stayed out of the repository.
Result
232 contacts researched and 93 emails sent the same day, with 0 send failures.
